## 1. 决定性负结果：九种视觉方法全部失败

用户提供 9 张真实数学练习页（一年级上，3072x4096），已导入。

**Lead 人工确认的真值**（逐张看高清裁切比对）：

| 关系 | 照片编号 |
|---|---|
| **同页双拍（正例）** | 1–7、2–8、4–9 |
| 各自独立页 | 3、5、6 |
| 特殊：整页 vs 局部近照 | 4 与 6（4 是整张跨页展开照，6 是同一张纸右半页近照） |

**九种方法都无法把同页对与不同页对分开**：

| 方法 | 同页对距离 | 不同页最小距离 | 结果 |
|---|---|---|---|
| dHash 9x8（64 bit） | 27, 24, 17 | 5 | 失败 |
| dHash 17x16（256 bit） | 118, 111, 119 | 79 | 失败 |
| dHash 33x32（1024 bit） | 518, 488, 493 | 361 | 失败 |
| dHash 65x64（4096 bit） | 2078, 2049, 2035 | 1839 | 失败 |
| dHash 129x128（16384 bit） | 8131, 8074, 8139 | 7913 | 失败 |
| aHash 9x8 / 17x16 / 33x32 / 65x64 | 全部失败 | | 失败 |
| dHash + `-trim` 裁留白（各分辨率） | 全部失败 | | 失败 |
| 纸面区域裁剪后再 dHash + 4 方向旋转 | 17, 31, 24 | 11 | 失败 |
| NCC 归一化互相关（64/128/256 画布） | 全部失败 | | 失败 |
| 墨迹密度图 NCC（16/32/48 网格） | 0.542 / 0.433 / 0.345 | **0.835** | 失败（**反向**：不同页更相似） |

**关键判断**：

- 不是分辨率问题——16384 bit 也失败
- 不是裁留白问题——`-trim` 与纸面包围盒裁剪都试过
- 不是对齐度量问题——NCC 也失败，且方向相反
- **4 方向旋转归一化救不回来**

**根因**：同页的两张照片是**完全不同的取景**——一张纸张竖直占满画面，另一张纸张在桌面背景中斜放、带大面积深色背景。真实同页双拍的差异（透视、背景、光照、纸张弯曲）**远大于**不同练习页之间的差异（同样的印刷版式、同样的题型、同样的田字格/竖式排版）。

**反面证据**：不同页的照片两两距离反而更近（3–6 d=11、4–6 d=5），正是因为版式高度相似——这正是 DESIGN §11.2 警告的「不同算术练习页可能版式高度相似，却题目、手写或批改不同」。

**环境约束**：node `sharp` 未安装；Python 无 numpy/scipy/opencv/imagehash（Pillow 有）；ImageMagick 无内置 phash；不新增原生依赖。

### 时间窗口召回也被否定

同页对在导入序列中分别相隔 **6、6、5** 个位置。所以「最近 3 页」召回 **0/3**。且 9 张照片**宽高完全相同**（都是 3072x4096），宽高比过滤也无效。

## 2. 推荐方案：降级为人工归组

**停止视觉指纹路线**，保留 Page/Capture 归组骨架：

- 新 Capture 进入「待整理」
- 用户选一张待整理 Capture → 看到**同分类最近 Page 的可滚动列表**（默认最近 12 个，**仅作导航，不称视觉候选**）
- 点任一 Page → 新旧原件**并排**
- 也可按原文件名 / Document 标题**搜索**全部 Page
- 只有两个显式动作：**「同一页，添加为另一张照片」** 与 **「不同页，创建新页面」**
- 图库默认一页一卡，首选图作封面，页内展示全部 Capture 并可更换首选
- 未归组 Capture 独立「待整理」区

依据：DESIGN §10.3 明确允许「候选不存在时也允许手动搜索已有页面」；§11.2 说「感知哈希**或其他简单指纹**」，未强制必须有指纹。

## 3. `visual_fingerprint` 两列的处理

**保留 schema，全部维持 NULL，不计算、不回填、不在 UI 展示。**

理由：冻结 DDL 允许 NULL；算法已证伪，写入只会制造无意义字节和未来误用风险。即使标注「仅供参考」，距离数字仍会形成虚假精确感并诱导排序。

**不创建 `visual-fingerprint.js`**，避免把已证伪算法留成可调用生产能力。**不需要 `sql/004_*.sql`**。

## 4. 数据模型（沿用上一版）

- 每个新 Page 建**独立 Document**：`source_type='other'`、`title=NULL`、`page_number=NULL`、`status='pending'`

## 5. HTTP API（5 条，全部鉴权）

> `dsh-host-webserver` 的 `WebRouteKind` 只有 `'exact' | 'prefix'`，**无路径参数**（已核实 `lib/types/index.d.ts:35-44`）。`:id` 一律改 query 参数或 JSON body 字段。

| 方法 | 路径 | 用途 | 契约要点 |
|---|---|---|---|
| GET | `/wrongbook/pages` | Page 列表 / 手动搜索 | query: `limit`(默认50,≤200) / `subject_code` / `term_code` / `q`。`q` 参数化 ILIKE + 转义 `%` `_` `\`。返回 PageCard 含 `preferredCapture`、`captureCount`、`latestCaptureAt`。首选为空时用页内最早 Capture 作临时封面并标 `displayCaptureSource='fallback'`，**不隐式写 preferred**。稳定排序 `latestCaptureAt desc, page.id`。**无 score 字段** |
| GET | `/wrongbook/pages/detail` | 单页 + 全部 Capture | `?page_id=<uuid>`。Capture 按 `created_at,id` 升序。只用已登记 `original_path` 生成 URL |
| POST | `/wrongbook/pages` | **不同页，创建新页面** | body `{capture_id}`，≤16KiB。事务建 Document+pending Page，锁 Capture，要求 `registered` 且 `page_id IS NULL`。重复提交 → `CAPTURE_ALREADY_GROUPED` 409（带当前 pageId）。**重试不得再建第二个 Document** |
| POST | `/wrongbook/pages/attach` | **同一页，添加为另一张照片** | body `{page_id,capture_id}`。锁 Capture + 校验目标 Page 存在 + `page_id IS NULL` 后更新。竞态 409，不存在 404 |
| POST | `/wrongbook/pages/preferred` | 更换首选 | body `{page_id,capture_id}`。锁 Page + 校验 Capture 属于本页。不属于 → `PREFERRED_CAPTURE_NOT_IN_PAGE` 409。**不得 DELETE 任何 Capture/文件，不得声称标准化图已更新** |
| GET | `/wrongbook/captures` | 保留旧契约 | 增加向后兼容的 `group=ungrouped`（`page_id IS NULL`）+ 分类筛选，**默认返回语义不变**。待整理区用 `group=ungrouped` |

## 6. 归组事务与并发

`createPage` 与 `attach` 都用单事务（`pool.connect` + BEGIN/COMMIT/ROLLBACK）：

1. 先 `SELECT capture FOR UPDATE`
2. 再以 `page_id IS NULL` 条件更新
3. 重复提交返回 `CAPTURE_ALREADY_GROUPED` 409

失败回滚只撤销元数据，**不删除、不移动、不重写任何原件**。本步不提供 Page 删除。

## 7. 滚动条缺陷（独立修复项）

**根因**（planner 只读核实宿主源码，非猜测）：

- `dsh-client-ui-layout` 的 `AppFrame` 的 `frame` 与 `centerCol` 均 `overflow: hidden`
- `mainPanel` 是 `flex: 1` + `min-height: 0` 的纵向 flex 容器
- `main` 的 `SlotOutlet` 是 `display: contents`，**不提供滚动包装**

⇒ `.wb-page` 没设 height/overflow 时，内容越过面板后被 `centerCol` **裁掉**。

佐证：官方 Plugin Manager 页自己也用 `height: 100%` + 内部 `overflow: auto`，说明这是插件页面的契约。

**修法**（独立小修，先于第 6 步功能）：

```css
.wb-page {
  box-sizing: border-box;
  width: 100%;
  height: 100%;
  min-height: 0;
  overflow-y: auto;
  overflow-x: hidden;
}
```

保留现有 `padding` / `max-width` / `margin`。**不给 body / document / 宿主 main 写样式，不依赖 window 滚动。**

**待验证**：需要真实页面复核 `scrollHeight > clientHeight`、滚到底可见、窄窗口、明暗主题、切换会话。本轮 Client Slots inspection 两次超时，源码核实不能替代视觉验收。

## 10. 变异测试设计

| 变异 | 期望变红 |
|---|---|
| 删 attach 的 `FOR UPDATE` 或 `AND page_id IS NULL` | 并发/重复归组测试（不得静默改挂或建两个 Page） |
