# 单文件导入纵切面 — planner 冻结规划（用户已批准）

## A. 上传协议

fetch POST raw body（Content-Type: application/octet-stream），元数据放 query 参数 subject_code / term_code，原文件名放 query 参数 filename。

上限 **32 MiB (33554432 字节)**，同时检查 Content-Length 和实际流式累计字节数，超限 413 PAYLOAD_TOO_LARGE。

## B. 执行顺序（固定）

1. 校验 subject_code / term_code（SQL 查字典，取 directory_name）
2. 创建 staging 文件：`originals_root/.wrongbook-tmp/<request-uuid>.upload`
3. 逐块 update sha256 + 写 staging，边收边算
4. close/sync staging
5. 预留 SQL：

```sql
INSERT INTO captures (sha256, original_path, original_filename, source_metadata_json, status)
VALUES ($1, $2, $3, $4::jsonb, 'reserved')
ON CONFLICT (sha256) DO NOTHING
RETURNING id, status, original_path
```

`$1` 用 32 字节 Buffer；`$2` 是先生成的碰撞安全相对路径。

6. 无 RETURNING 行 → SELECT 既有行，按 status 分支（registered → duplicate；reserved/copied → 恢复）
7. 预留成功者才复制：同目录唯一临时名 + `fs.rename` 原子发布
8. 重算最终文件 SHA-256 与预留 digest 比对，不符 → HASH_MISMATCH 500，**不覆盖不删除**
9. identify 读 media_type / width / height
10. `UPDATE ... SET status='copied', media_type=$2, byte_size=$3, width=$4, height=$5, last_error=NULL WHERE id=$1 AND status='reserved'`
11. `UPDATE ... SET status='registered' WHERE id=$1 AND status='copied'`

**page_id 全程保持 NULL。**

## C. 并发

`ON CONFLICT(sha256) DO NOTHING` 是唯一仲裁点。不先 SELECT 再 INSERT。

预留失败后的记录**不 DELETE**，只同状态 UPDATE last_error 保留现场。

## D. 文件名

`YYYYMMDD-HHMMSS.<sha256前12hex>-<randomUUID去横线>.<identify确认的小写扩展名>`

例：`20261126-235959.a1b2c3d4e5f6-018f2b....jpg`

相对路径固定 `${subject.directory_name}/${term.directory_name}/${storageName}`

## E. 路径安全

只用 `path.posix.join` 拼相对路径；`resolveOriginal` 先 `path.resolve` 再校验 `final.startsWith(root + path.sep)` 且相对路径符合 captures 的 CHECK 规则；用 `realpath` 防 symlink 越界。

**绝不接受客户端传 directory_name 或路径。**

## F. 图片探测

`identify -format "%w %h %m"` 读真实字节，**不信 File.type / 扩展名**。

只白名单映射 JPEG→`image/jpeg`、PNG→`image/png`（HEIC 需实测后再加）。

输出不匹配 `/^(\d+) (\d+) ([A-Z0-9]+)$/`、非零退出、超时 10s → 422 IMAGE_PROBE_FAILED。

多帧图片（identify 输出多行）→ 直接 422。

## G. 错误 envelope

失败：`{ok:false, error:{code, message, retryable}}`
成功：`{ok:true, outcome:"imported"|"duplicate", capture:{...}}`

| 错误码 | HTTP |
|---|---|
| UNAUTHENTICATED | 401 |
| FORBIDDEN_ORIGIN | 403 |
| INVALID_SUBJECT_CODE / INVALID_TERM_CODE | 400 |
| INVALID_FILENAME | 400 |
| UNSUPPORTED_MEDIA_TYPE | 415 |
| EMPTY_UPLOAD | 400 |
| PAYLOAD_TOO_LARGE | 413 |
| UPLOAD_ABORTED | 400 |
| STAGING_WRITE_FAILED | 500 |
| ARCHIVE_COPY_FAILED | 500 |
| HASH_MISMATCH | 500 |
| IMAGE_PROBE_FAILED | 422 |
| DATABASE_UNAVAILABLE | 503 |
| CAPTURE_RECOVERY_REQUIRED | 409 |
| NOT_FOUND | 404 |

响应绝不写本机绝对路径、SQL、stack。

## H. UI 最小结构

科目 select、学期 select、file input（`accept="image/*"`，不加 multiple）、导入按钮、状态文本、结果卡片含 `<img src=original_url>`。

下方图库区：刷新按钮 + Capture 卡片列表（显示分类、原文件名、宽高、大小、状态、图片）。

成功后清空 `input.value` 以便重复选同一文件。

## I. 新增路由

- `POST /wrongbook/import`
- `GET /wrongbook/captures`
- `GET /wrongbook/originals/*`

三条路由的 handler **第一行都要 requestRejection 鉴权**。

`/originals/*` 只按 DB 里已登记的 original_path 读文件，不接受客户端任意路径。

## L. 已确认的安全缺口（必须修）

Lead 实测：

```
无 cookie GET /wrongbook/health → 200   ← 当前无鉴权
无 cookie GET /          → 401         ← 框架首页有鉴权
```

修法：apply 的 inject 加 `connection`，在 handler 开头调：

```js
const rejection = ctx.connection.requestRejection({ headers: req.headers })
```

返回 401 或 403 时直接 `sendJson(res, rejection, {...})` 并 return。

已核实该 API 存在于 `dsh-connection`（`requestRejection(request)` → 403/401/undefined）。
